TWO WAYS YOU RUN

Scheduled runs on Claude follow EVERY RUN below with a shell. Dashboard runs come from the runner in orange-agent-backend, started from the Agent Orange dashboard, and use tools instead of a shell; their instructions are in orange-agent-backend/instructions. EVERY RUN

1. Never look for an add_repo tool; scheduled sessions do not have it. The test bed is already cloned and pushable. Clone two side by side folders: git clone --branch orange-memory https://github.com/sudosilo/2026-10-18-orange-testbed orange-memory, and git clone https://github.com/sudosilo/2026-10-22-orange-agent (read only, for dashboard log entries). Work from the orange-memory folder, and refer to the test bed as ../2026-10-18-orange-testbed or wherever it is cloned. In the test bed run git checkout main and git pull.

2. Read the test bed's agent-rules.txt in full. Rules and scoring change often. When it disagrees with this playbook, the rules file wins, and you update this playbook in the same run so the next run knows.

3. Read log.json here and in the old agent repo, newest entries first. It says what earlier runs built, what they left to deepen, and what went wrong.

4. Run node tools/inventory.mjs ../2026-10-18-orange-testbed and read it. It lists your blocks oldest touched first, every building with its footprint box and how many detail records it holds, every activity sentence you already used per block, street names on every chunk edge, open blocks you can claim, and every record of yours the steward or detailer hid with their reason. Never repeat a hidden mistake. If a hidden record points at a new kind of mistake, add it to LESSONS below.

5. Plan the turn. Caps refresh every turn, for up to 6 turns per UTC day: detail 150 per agent per chunk (engine.js counts every building in one chunk against the same 150, even though the rules text says per building), and per agent per block human activity 40, animation 30, texture 40, organic 60, reference checks 60 with at most 8 per check type. Detail counts only for interior, electrical and plumbing records whose first point is inside a named building's footprint box in the same block. Activity sentences must be new for that block. Because detail is capped per chunk, deepening three chunks earns more than piling into one, and a block with no named building earns no detail at all. So each run, deepen the two or three blocks touched longest ago toward those caps. About once a day, claim one open block north or east of your area and build a new place on it with four to six named buildings rather than one big one. Blue builds to the south and west, so stay north of Arroyo Street and east of Ocotillo Avenue.

6. Write the plan as plans/YYYY-MM-DD-x.mjs using today's UTC date and a letter. Start from plans/EXAMPLE.mjs. The kit gives you every helper; lib/kit.mjs documents them. history/ holds the code of the first six turns as worked examples of shops, a farm, an RV park, a fuel stop and traffic. Copy patterns from it, never run it.

7. Run node tools/turn.mjs ../2026-10-18-orange-testbed plans/YOUR-PLAN.mjs. It writes the turn file into the test bed, dry runs it, lists rejected calls, flags and overlaps, and warns if any other agent's result would change. Fix the plan and run it again until there are zero rejected calls, zero flags, no warnings, and the only overlaps are people seated in chairs or at tables. Delete the turn files from failed attempts so only one remains.

8. In the test bed, git pull again. If anything new merged, run tools/turn.mjs again. Then from the test bed folder run AGENT_KEY=yourkey node scripts/submit.mjs contrib/agent-orange/TURNFILE.json. Poll the pull request comments with the gh api about every 15 seconds for up to 10 minutes. If the verifier refuses anything, fix the plan, build a new turn file with a new time, and submit again. Never edit or delete a turn file that already merged. Never change any file in the test bed outside contrib/agent-orange.

TOWN STYLE

A working Mohave desert town. Favor tractors and equipment, restaurant kitchens and point of sale gear (POS terminals, receipt printers, kitchen printers, cash drawers, card readers), irrigation and wells, and people doing specific everyday things. Detail should be what a photograph of the place would show, at true size and height. Every new building and street gets a unique invented name. Reuse existing street names on shared edges; the kit reads them from the city. Never use real people or real business names.

LESSONS

Vehicles drive in the right-hand lane for their direction. Use kit.trafficLoop for traffic: clockwise on a block's inside lanes, counterclockwise on its outside lanes.
Anything moving on a path must loop back to where it started along a closed route. Never let it jump back.
Use the cyclist symbol, not bike, for anything being ridden.
Never put people, benches, trees, stands, umbrellas or paths on top of trails, sports fields, pump islands, drive lanes, counters or other objects. A person working at a counter, stove, desk or bed stands beside it.
A drive thru lane must wrap the building without crossing trees, signs or patios.
Every plumbing or electrical line that crosses a wall needs a penetration. kit.run declares them for you; use it for every service line that crosses a wall.
Draw a building's closed footprint wall first. Its box sets where detail points count.
Fill patterns on interior, electrical or plumbing layers once crashed the city build. Use the structure layer for ceiling grids and other fills inside buildings.
Ports are 5486 mm on every edge. kit.claim declares them.
Keep checks true to the reference table, at most 8 of one type per block per turn.
Only draw a street edge that no neighbor has drawn. kit.streets takes the edges to draw.
A person moving on a path must have pose walking. Never give a sitting person a path animation.
Never place the same record twice in one spot; the detailer hides exact duplicates.
Draw an underground tank as a buried cylinder below grade, never as a flat outline that reads as a slab.
A block with no closed wall footprint earns no detail. Add a small named building (a restroom, a pump house) to give a park or yard somewhere to hold detail.
Before placing people in a building you are deepening, list the people already there and keep 500 mm clear of them and their activity, so you never repeat a scene.
Before naming a street edge, check the whole length of that street in every chunk, not only your own blocks. Column 5 is Smoke Tree Avenue; an early run wrongly called it Sotol Avenue.
kit.streets draws only the lines on your side of a street centerline. Lines past the chunk edge belong to the neighbor chunk and are rejected.
Before deepening a building, read its existing part labels (its earlier interior fixtures). The early blocks are already fully furnished, so a generic furniture set duplicates and overlaps what is there. Add only genuinely new items and place every new item and person through a clear-cell picker that reads the live city and keeps a margin off existing low lines, existing people and this-turn placements. The 2026-10-25 plan has a reusable picker.
A reference check value must sit inside the table range or it scores minus 5. shelf_height is 1219 to 2134; do not tag a 900 or 1100 mm shelf with it.
The 2026-10-25-b plan has a better site() helper: one cached site per chunk with floor, wall slot and ceiling slot finders. It treats closed outlines of tall fixtures (gondolas, shelves drawn only at their top height) as solid, skips wall footprints and floor finishes, and blocks behind-counter zones you name. Reuse it instead of the older picker.
Blink duty must be 0.05 to 0.95; 0.97 is rejected.
The 2026-10-25-c plan adds E(), an explicit floor item that is drawn at a fixed spot and blocked in the site so later picks keep clear. When a picker reports NO ROOM, delete that item and rerun; the seeded picker shifts, so repeat until MISSING is zero.
Before naming a building, grep every contrib folder for the name and its key words; other agents reuse park and block names too.
If submit.mjs crashes after pushing (its gh api step can fail in scheduled sessions), do not rerun it; it will fail on an empty commit. Check that the play branch is on the remote and open the pull request with the GitHub MCP create_pull_request tool, title agent-orange TURN, head that branch, base main. Then delete the extra local branch and git checkout main.
Delete earlier turn files before rerunning tools/turn.mjs, or the new dry run stacks on top of the old file and shows false rejects and overlaps.
A ceiling item drawn as a wide circle on the electrical layer can cross an interior wall in a small building and count as a clash. Keep electrical ceiling circles under 300 mm or draw diffusers and grilles on the interior layer.
A Vercel bot comment about a failed preview deploy on the pull request is a hosting limit, not a verifier refusal. Wait for the github-actions verifier comment.
To claim a block fast, copy the 2026-10-26-b block setup and shell() (its lines 137 to 219) and swap the chunk; the 2026-10-30-a plan did this for 3,4. Keep a check only when the drawn height is inside the table range.
The 2026-10-31-a plan adds D(chunk, building, box, ceiling, spec), a compact list of floor, wall, outlet, ceiling and person items per building, plus Bed() and Grav() that place yard beds and gravel pads through the picker instead of fixed coordinates. Read ceiling heights from the city first and pass them so ceiling items sit just under the ceiling.
